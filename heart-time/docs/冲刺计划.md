# 冲刺计划

## 一、阶段目标

本阶段（Alpha 冲刺）的核心目标是：

# 完成系统整体骨架搭建与核心功能链路跑通

```text
用户输入
→ 前端交互
→ 后端调度
→ AI层处理
→ 返回结果
```

确保系统具备最基础的：

- 前后端通信能力
- AI模块调用能力
- 基础数据流转能力
- 模块协作能力

同时，在本阶段重点建立：

- 工程规范
- 模块边界
- 接口契约
- 团队协作流程

为后续 Beta 阶段功能扩展和系统优化奠定基础。

## 2. 当前存在的问题

在前期讨论与实现过程中，也暴露出一些问题。

------

### （1）模块边界尚不清晰

目前：

- AI层
- 后端层
- 数据层

之间职责划分仍不够明确。

例如：

- AI逻辑是否进入后端
- 后端是否直接调用模型
- 数据管理归属

等问题尚未完全规范。

------

### （2）接口规范尚未统一

目前不同成员之间：

- 请求格式
- 返回格式
- 参数命名

尚未形成统一规范。

容易导致：

- 联调困难
- 模块耦合
- 后期修改成本增加

------

### （3）工程化意识仍在建立阶段

当前更多处于：

```text
“功能实现”
```

阶段。

而对于：

- 日志
- 测试
- 异常处理
- 项目结构
- 代码规范

等工程化内容考虑较少。

------

### （4）团队协作流程不完善

目前：

- 任务边界
- 提交规范
- 迭代记录
- 会议记录

尚未形成统一流程。

后期可能导致：

- 工作重复
- 责任不清
- 进度失控

------

# 三、Alpha阶段改进思路与方案

## 1. 建立统一系统架构

本阶段统一采用：

# 前端 + 后端 + AI模块

的分层结构。

推荐结构：

```text
frontend/
backend/
    api/
    service/
    ai/
    schemas/
```

其中：

------

### 后端负责

- API接口
- 用户请求调度
- 数据流转
- 系统业务逻辑

------

### AI层负责

- Prompt
- Memory
- RAG
- Agent
- LLM调用

------

## 2. 建立统一接口规范

统一：

### 请求格式

```json
{
  "user_id": "001",
  "message": "你好"
}
```

------

### 返回格式

```json
{
  "response": "...",
  "status": 200
}
```

减少联调成本。

------

## 3. 建立工程规范

包括：

------

### （1）项目结构规范

统一：

- 文件命名
- 模块划分
- 路由组织

------

### （2）Git提交规范

例如：

```text
feat:
fix:
refactor:
docs:
```

------

### （3）日志与迭代记录

每次迭代记录：

- 完成内容
- 当前问题
- 下一步计划

形成开发过程文档。

------
